## Recovered Issue Summary (in place of spec Q1/Q2/Q5/Q6/Q9/Q10/Q14)

- **Issue:** `WmVideo.renderWidget` (in `rn-runtime-mars`, `video.component.tsx`) does not guard against `videoService`/`VideoView` being `undefined`, and crashes on preview. Suspected root cause: an expo-video native module registration gap under Expo Go vs. a `dev-client`/`expo prebuild` native build.
- **Fix approach:** add a fallback guard in `renderWidget` instead of crashing; null-check `videoSource` inside `initializePlayer`.
- **Current props exposed today (per notes):** `mp4format`, `webmformat`, `videoposter`, `showdefaultvideoposter`, `controls`, `autoplay`, `allowsPictureInPicture`, `requiresLinearPlayback`, `onFullscreenEnter`/`onFullscreenExit` — a thin slice predating later expo-video SDK additions.
- **Edge cases already identified:** dual mp4/webm source unsupported-format fallback; loop+autoplay+poster interaction; multiple `WmVideo` instances inside a repeating container (players leaking/colliding); switching source mid-playback (`replace()` vs. remount); web vs. native no-op differences.
- **Backward compatibility:** fix must not introduce any new required prop or change default behavior for apps already using `WmVideo` with the original prop set.
- **Regression coverage:** currently **zero** unit tests exist for `WmVideo`'s render/init path — this is itself a gap the OKR calls out ("Add regression test coverage (currently zero)").
- **Verification checklist (per team standard):** Web preview → Expo Go Android/iOS → `expo prebuild` → native builds Android/iOS.
