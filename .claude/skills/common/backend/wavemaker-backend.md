# WaveMaker Backend APP Composition
- Backend is based on Spring 6 and Servlet 6 (Jakarta) with Maven as build system
- It strictly follows traditional Spring XML configuration and **not** Spring Boot
- All services imported in the application are present in the `services` folder with service id as the name of the folder
- These folders are auto-generated by WaveMaker Studio and should not be edited manually
- Services like `JavaService`, `SoapService`, `RestService`, `OpenAPIService`, `WebSocketService`, `DataService`, `SecurityServiceType` contain generated Java code
- These services follow Spring standards and are beans that can be autowired

## JavaService vs Custom Code

WaveMaker supports two ways to write backend logic: **JavaService** and **Custom Code**. Understanding the distinction is critical.

### JavaService (WaveMaker-Managed)
JavaService is WaveMaker's low-code approach **exclusively for exposing APIs** from your application. You only write service-layer methods and WaveMaker automatically handles the rest — generating controllers, service interfaces, and bean definitions.

### Custom Code (User-Managed)
Custom code refers to any user-written files within the `src/` directory. Unlike JavaService, WaveMaker provides **no auto-generation** for any of these. Custom code is for any configuration or implementation requirements other than exposing APIs — for API exposure, always use JavaService.

## CRITICAL RULES

- Only **JavaService** files and custom code within the `src/` directory may be modified. Other service types such as RestService, SoapService, OpenAPIService, WebSocketService, DataService, SecurityService, etc. — their Java and XML files must not be edited — unless a **loaded skill** explicitly permits it (e.g. security configuration, dependency edits per that skill).

## Service Management
- **platform_getAllServiceIds** (No args): Returns all service IDs registered in the project.
- **platform_deleteService** (Required Args): Permanently deletes an existing Java service and all its associated files. Use only when explicitly instructed to remove a service.

## Compile Project
- **platform_compile** (No args): Compiles the WaveMaker project. Use this after making code changes to verify the build succeeds.

FINAL CHECK: Before submitting any code changes, you MUST strictly follow the critical rules and the loaded skill instructions.
